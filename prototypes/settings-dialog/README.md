# 設定 GUI の試作（#38、捨てブランチ）

ADR-0004（設定 GUI は Win32 コモンコントロールのモードレスダイアログ）が成り立つかを、実機で 2 点確かめるための試作。main にはマージしない。

1. DPI の違うモニタ（150% と 100%）の間でダイアログを動かしたときに、文字・配置・タイトルバーのダークモードが崩れないか。
2. サブクラス化した hot key control に、Esc・矢印・Ctrl+`+` が入るか。

## 作りの概要

- `settings.rc` の `DIALOGEX` を `CreateDialogParamW` でモードレスに開く（`IsDialogMessageW` を通すメッセージループ）。
- Per-Monitor V2 と Common Controls v6 は `app.manifest` をリンカで埋め込む（`/MANIFEST:EMBED`）。
- タイトルバーのダークは `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)`。
- `.rc` は `build.rs` が Windows SDK の `rc.exe` でコンパイルし、`.res` をリンカ引数で渡す。追加の crate は使っていない（`windows` だけ）。`rc.exe` の場所は `RC` 環境変数で上書きできる。
- hot key control（`msctls_hotkey32`）は `SetWindowSubclass` でサブクラス化する。
  - 既定: `WM_GETDLGCODE` に `DLGC_WANTALLKEYS` を足して返すだけ（ADR-0004 の案）。キー自体は標準の処理に任せる。Tab / Shift+Tab だけはフォーカス移動のためダイアログに任せる。
  - チェックボックス「WM_KEYDOWN / WM_SYSKEYDOWN もサブクラスで横取りする」をオンにすると、キー押下をサブクラスで受け、修飾キーの状態と合わせて `HKM_SETHOTKEY` で値を入れる（標準の処理には渡さない）。既定の方式でうまく入らないキーがあったときの回避策の候補。
- DPI の処理は 2 つのモードを切り替えられる（「DPI モード切替（開き直す）」ボタンで、同じ位置にダイアログを開き直す）。
  - 自動: PMv2 のダイアログマネージャに任せる（`WM_DPICHANGED` を既定の処理に渡す）。
  - 手動: `SetDialogDpiChangeBehavior(DDC_DISABLE_ALL)` で自動の処理を止め、`WM_DPICHANGED` で提案された矩形に合わせ、フォント（Segoe UI 9pt）を作り直し、子コントロールの位置と大きさを作成時の DPI からの比で置き直す。

画面の表示:

- 「現在の値」: `HKM_GETHOTKEY` の値（修飾キー + キー名、vk、拡張キーなら `ext`、生の値）。
- 「キー履歴」: 入力欄が受けたキー押下と、その後の値。`WM_DPICHANGED` もここに出る。ダイアログ側が `IDOK` / `IDCANCEL` を受けたとき（＝ Enter / Esc が入力欄に届かなかったとき）もここに出る。
- 下の行: 今の DPI、クライアント領域の大きさ（px）、DPI 処理のモード、ダークのオン・オフ、直近の状態。

## 確かめる手順

前提: 150% のモニタと 100% のモニタが横に並んでいる（3 枚構成のうち 2 枚を使う）。キーボード配列（JIS / US）を結果に書く。

`C:\Users\jiji\shunsoku-build\settings-dialog\settings-dialog.exe` をダブルクリックで起動する。

### 1. DPI の違うモニタ間の移動（文字・配置・ダークのタイトルバー）

各モード（自動 → 手動の順）で次を行う。起動直後は「自動」。

1. 150% のモニタにダイアログを置く。下の行が `DPI 144（150%）` になっていることを確かめ、スクリーンショットを撮る。
2. タイトルバーをドラッグして 100% のモニタへ移す。モニタの境界をまたいだ瞬間と、移し終えた後を見る。
   - 文字: ぼやけ・欠け・はみ出し・大きさのちぐはぐ（コントロールごとに大きさが違う）がないか。1 行目の日本語（全角・半角カナ・漢字）も見る。
   - 配置: コントロール同士の重なり、ダイアログの端での切れ、余白の偏りがないか。コンボボックスを開いたときのリストの高さ、キー履歴のリストボックスの行の高さも見る。
   - タイトルバー: ダークのままか、移動中にちらついて明るくならないか。
   - 下の行が `DPI 96（100%）` になり、クライアントの大きさがおおよそ 150% のときの 2/3 になっていること。
   - スクリーンショットを撮る。
3. 100% から 150% へ戻し、同じ点を見る。何往復かして、往復で大きさがずれていかないか（クライアントの px が元に戻るか）も見る。
4. ダイアログの半分ずつが両方のモニタにかかる位置で止め、どちらの DPI になるか、表示が崩れないかを見る。
5. 「ダーク切替」を押し、タイトルバーが明るく・暗く切り替わるか（すぐに切り替わるか、フォーカスを外したときに切り替わるか）を見る。ダークに戻しておく。
6. 「DPI モード切替（開き直す）」を押して「手動」で開き直し、1〜4 を繰り返す。
7. （任意）150% のモニタ上で起動した場合と、100% のモニタ上で起動した場合の両方を試す（開き直しは同じ位置に開くので、起動時の DPI を変えたいときは移してから開き直す）。

### 2. hot key control への Esc・矢印・Ctrl+`+`

各方式（チェックボックスのオフ → オンの順）で次を行う。入力欄をクリックしてフォーカスを入れてから押す。1 つ押すごとに「クリア」で空にしてよい。

1. Esc を押す。
   - 期待: 「現在の値」が `Esc(vk=0x1B)` になる。
   - 失敗の兆候: 値が変わらない、キー履歴に「ダイアログが IDCANCEL を受けた」が出る、値が「なし」に戻る。
2. ← ↑ → ↓ を 1 つずつ押す。
   - 期待: `Left(vk=0x25,ext)` などになる（`ext` が付き、テンキーの `Num 4` などと区別される）。フォーカスが他のコントロールに移らない。
3. Ctrl+`+` を押す。
   - JIS 配列: `+` は Shift+`;` なので Ctrl+Shift+`;` になる。期待値は `Ctrl + Shift + ;(vk=0xBB)`（VK_OEM_PLUS）。
   - US 配列: Ctrl+Shift+`=` で `Ctrl + Shift + =(vk=0xBB)`。
   - テンキーの `+` で Ctrl+`+`: `Ctrl + Num +(vk=0x6B)`（VK_ADD）。
   - Shift 抜きの Ctrl+`;`（JIS）/ Ctrl+`=`（US）も試し、`+` の代わりにこちらを既定にできるかの材料にする。
4. 参考として、Enter、Ctrl+Esc、Alt+矢印、Shift+矢印、Tab（フォーカスが次へ移るのが期待）も押してみる。
5. チェックボックスをオンにして 1〜4 を繰り返す。
6. 気になった挙動はキー履歴の行を書き写すか、スクリーンショットを撮る。
