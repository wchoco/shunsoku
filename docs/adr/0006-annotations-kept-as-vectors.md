# 書き込みはベクタのまま持ち、焼き込まない

スクラップの書き込みは、図形と文字列の記録（元の画像の座標で、色・太さ・文字サイズ・書体を持つ）として `ScrapModel` に持ち、スクラップの画像には焼き込まない。表示のたびに画像の上へ描き、保存とコピーのときだけ、表示と同じ描画処理で画像の画素の大きさに描いてから出力する。書き込みの編集モードを抜けたあとも書き込みを選び直して直せること、トリムの解除で隠れた書き込みが戻ること、ごみ箱から書き込みと履歴ごと復元できることを、どれも記録を持ち続けるだけで実現するために選んだ。決定の経緯は [spec: M4 書き込み](https://github.com/wchoco/shunsoku/issues/35) にある。

## Considered Options

- **モードを抜けるときに画像へ焼き込む**: 保存とコピーは元の画像を出すだけで済み、記録も持たなくてよい。その代わり、抜けたあとは直せない。トリムの外の書き込みも切り落とされる。元に戻すには、画像を丸ごと履歴に積む必要がある。
- **記録と焼き込んだ画像の両方を持つ**: 表示は速くなるが、どちらが正しいのかを常に揃え続ける必要がある。書き込みは小さいので、毎回描いても重くならない。

## Consequences

- 出力と表示を合わせるには、描画処理を 1 つにしておく必要がある（`render` の同じ関数で、表示にも保存とコピーにも描く）。
- 書き込みを含めない出力や、書き込みをファイルへ保存することは、MVP では扱わない。
- トリムと拡大縮小は表示の変換を変えるだけにする。書き込みの座標は変えない。
