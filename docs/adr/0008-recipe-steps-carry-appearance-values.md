# 見た目の値はレシピの操作にパラメータとして添え、名前付きのプリセットは作らない

見た目（透明度、枠を出すか・色・太さ、影の有無）を値で指定する操作は、レシピに並べるときにだけパラメータを添えて呼ぶ。`steps` にはパラメータのない操作（操作の id の文字列）とパラメータを添えた操作（`{ op = "appearance", border_color = "#FF0000", border_width = 3 }` のような表。キーは `[scrap]` と同じ）を混ぜて並べる。ショートカット 1 つで値を指定したいときは、操作が 1 つのレシピを作る。名前付きの見た目のプリセットを設定に並べる案もあったが、プリセットは「名前を付けた設定のまとまりで、ショートカットから呼ぶ」という役目がレシピと重なる。プリセットを作ると、同じことをする仕組みが 2 つになるため採らなかった。ADR-0007 で決めた「引数のある操作はレシピに入れられない」のうち、`appearance` だけはこの ADR で例外にする。

## Considered Options

- **名前付きの見た目のプリセット**: プリセットごとに値のない操作ができ、メニュー・ショートカット・レシピのどこからでも名前で呼べる。その代わり、設定にレシピと並ぶ一覧がもう 1 つ増え、設定 GUI のタブも増える。
- **右クリックメニューから値を入れるウィンドウ**: その場で任意の値を指定できる。ただし Win32 のウィンドウが 1 つ増える。今は必要ないので見送り、要るようになったら足す。

## Consequences

- パラメータに書いた項目だけを、スクラップごとの上書きに重ねる。書かなかった項目は今の値のまま残る。全部を消して既定値に戻すには、パラメータのない操作「見た目を既定に戻す」を使う。
- 色か太さを書いたパラメータは、枠を出す指定も含む。`border = false` と色・太さを同時に書くのは矛盾なので、レシピの問題にする。範囲外の値、書式の誤り、知らないキー、項目を 1 つも書いていないパラメータも、レシピの問題にする（値を丸めて実行はしない）。
- 枠の太さもスクラップごとに上書きできるようにする。太さが変わってウィンドウが広がっても、画像の画面上の位置は動かさない。
- 見た目がもう指定どおりでも、その操作は成功として扱い、次の操作へ進む。
