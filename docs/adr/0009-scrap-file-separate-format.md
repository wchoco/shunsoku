# 開き直せる保存は、保存画像とは別の専用のスクラップファイルにする

書き込みを直せる形のまま保存して開き直すために、保存画像（PNG）とは別に、専用の拡張子 `.shunsoku` のスクラップファイルを書き出す。中身は元の画像（トリム前の画素。白紙スクラップなら背景色と大きさ）、書き込み、トリムの範囲と、形式の版。元に戻す・やり直すの履歴、画面上の位置、倍率、見た目の個別値は入れない。PNG に記録を埋め込む案もあったが、書き込みを合成した画像と元の画像を両方持つことになる。そうするとファイルが倍の大きさになり、2 つの中身がずれたときにどちらが正しいかも決められなくなるため、採らなかった。ADR-0006 の「書き込みをファイルへ保存することは MVP では扱わない」は、この ADR で解禁する。

## Considered Options

- **PNG の独自チャンクに記録を埋め込む**: ほかのアプリでもそのまま画像として開ける。その代わり、見える画素（合成した画像）と、元の画像と書き込みの記録とを両方持つことになる。ほかのアプリで画像を編集されると、記録とずれる。

## Consequences

- 保存画像とスクラップファイルは、それぞれ別のスクラップ操作で書き出す。スクラップファイルへの保存は毎回保存先を聞き、開いたファイルを覚えて上書きすることはしない。
- 開く入口は、トレイのメニューの「開く…」と CLI。拡張子の関連付けとドラッグ＆ドロップは扱わない。
- 開くアプリが知らない新しい版のファイルは開かずに、通知で知らせる。
