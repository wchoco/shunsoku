# レシピは 1 手ずつ進め、Effect の結果を待ってから次の手へ進む

レシピ（スクラップ操作の並び）は、まとめて 1 度に実行しない。1 手ずつ実行し、その手が返した `Effect` の結果を Win32 層が知らせてから次の手へ進む。結果は「成功」「失敗」「取り消し」のどれか。成功なら次の手へ進み、失敗か取り消しならそこで止める。どこまで進んだかと、結果を受けて次に何をするかは、core の純粋な状態機械が持つ。Win32 層の `app` は Effect を実行し、その結果を状態機械へ返すだけにする。「保存して閉じる」で保存に失敗したときにスクラップを閉じないためと、既定の保存（裏のスレッドで書き込み、結果は `WM_APP_SAVED` で届く）やクリップボードへのコピーのように、あとから失敗がわかる手を扱うために選んだ。

## Considered Options

- **レシピを core の 1 つの `Effect` にする、または全部の手の Effect を連結して 1 度に返す**: ADR-0005 の形のままで済む。ただし保存の失敗やダイアログの取り消しを知ったときには、後ろの手（`close` など）がもう走っている。
- **Win32 層だけでレシピを回す**: 「どの結果なら次へ進むか」の決まりがテストの境目の外に出てしまう。

## Consequences

- 今の Effect は実行したら終わりで、結果を返さない。レシピから走らせた手については、クリップボードへのコピー、保存、名前を付けて保存のダイアログ、描画の失敗の結果を、状態機械へ返す道を通す。
- レシピは右クリックメニューに出さず、ショートカットからだけ呼ぶ。`trim` と `annotate` はモードを切り替えて入力を奪うので、レシピに入れられない。`close` はレシピの最後にだけ置ける。
