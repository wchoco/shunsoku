# レシピは操作を 1 つずつ進め、Effect の結果を待ってから次の操作へ進む

レシピ（スクラップ操作の並び）は、まとめて 1 度に実行しない。並べた操作を 1 つずつ実行し、その操作が返した `Effect` の結果を Win32 層が知らせてから次の操作へ進む。結果は「成功」「失敗」「取り消し」のどれか。成功なら次の操作へ進み、失敗か取り消しならそこで止める。どこまで進んだかと、結果を受けて次に何をするかは、core の純粋な状態機械が持つ。Win32 層の `app` は Effect を実行し、その結果を状態機械へ返すだけにする。「保存して閉じる」で保存に失敗したときにスクラップを閉じないためと、既定の保存（裏のスレッドで書き込み、結果は `WM_APP_SAVED` で届く）やクリップボードへのコピーのように、あとから失敗がわかる操作を扱うために選んだ。

## Considered Options

- **レシピを core の 1 つの `Effect` にする、または全部の操作の Effect を連結して 1 度に返す**: ADR-0005 の形のままで済む。ただし保存の失敗やダイアログの取り消しを知ったときには、後ろの操作（`close` など）がもう走っている。
- **Win32 層だけでレシピを回す**: 「どの結果なら次へ進むか」の決まりがテストの境目の外に出てしまう。

## Consequences

- 今の Effect は実行したら終わりで、結果を返さない。レシピから走らせた操作については、クリップボードへのコピー、保存、名前を付けて保存のダイアログ、描画の失敗の結果を、状態機械へ返す道を通す。
- レシピは右クリックメニューに出さず、ショートカットからだけ呼ぶ（キャプチャで始まるレシピはホットキーから呼ぶ。ADR-0010）。`trim` はモードを切り替えて入力を奪うので、レシピに入れられない。`close` はレシピの最後にだけ置ける。`annotate` も入力を奪うが、最後の操作なら入ったところでレシピが終わるので、`close` と同じく最後にだけ置ける（#159）。最後にだけ置ける操作はレシピに 1 つまで。
- 最後にだけ置ける操作と対になる、最初にだけ置ける操作（キャプチャ系の操作）がある。最初の操作が撮ってスクラップを作り、残りの操作はそのスクラップで進める（ADR-0010）。
