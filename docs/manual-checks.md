# 手で確かめる項目

自動テストで確かめられない項目（Win32 の画面・入力・DPI・実機の配布物）を、M1〜M5 の spec の「手で確かめる項目」から 1 つにまとめた。
リリース（v0.1.0 など）の前に、全項目を通して確かめる。

- 前提の環境: Windows 11 の実機で、3840×2160 @150% が 2 枚と 1920×1080 @100% が 1 枚の構成（「3 枚構成」）。HDR の項目は、HDR を有効にできるモニタで確かめる。
- 確かめる UI: 全項目は片方の言語の UI で通す。もう片方の言語では、「言語」の列が「両方」の項目（文言が出る項目）だけを確かめる（M5-26）。CLI の文言は日本語のまま。
  - 文言が出る項目は、期待する結果がメニュー、通知、設定 GUI、範囲選択の画面の文字（サイズ・名前・座標）、書き込みのツールバー、ダイアログに出るものを見る項目。
  - 理由: v0.1.0 の前の通し（#104）は全項目を両方の言語で通し、約 2.5 時間かかった。言語で変わるのは文言と、それに引きずられる配置だけで、撮影・保存・CLI などの振る舞いは言語によらない。そこで、両方で通す範囲を文言が出る項目に絞った（[#112](https://github.com/wchoco/shunsoku/issues/112)）。
- 判定の列: その項目をどう判定するか。
  - 値: ファイル、ログ、レジストリ、終了コード、コントロールの文字や大きさで判定できる。
  - 目視: 画像を見ないと判定できない。ぼやけ、ちらつき、枠の見た目、スクラップに描かれたものなど。
  - 人: エージェントには操作できない。サインインのし直し、通知のクリック、IME、UAC、モニタの抜き差しや並び替え、HDR、別の PC など。人が確かめる。
  - 自動: 自動テストにした。手では通さない。CI（`windows-latest`）の `cargo test --workspace` で走る。「自動（実機）」は `#[ignore]` のテストで、通しの前に実機で 1 回走らせる（`docs/agents/windows-dev.md` の「実機でだけ走らせるテスト」）。かっこの中はテストの名前。
- エージェントが確かめるときは、`tools/win-driver` を通して操作し、[docs/agents/manual-check.md](agents/manual-check.md) の決まり（安全、結果の書き方、判定の仕方）に従う。
- 確かめる exe: リリースの workflow が作った zip を展開したもの（M5-18、M5-19）。
- 番号は `<マイルストーン>-<spec の番号>`。マイルストーンの後に足した spec やチケットの項目は、足した先のマイルストーンの表の後ろに続きの番号で足す。手順と期待する結果は、各 spec の表のまま写した。後のマイルストーンで振る舞いが変わった項目は、表の後の「置き換わった項目」に書いた。そちらを優先する。
- 出典: M1 [#32](https://github.com/wchoco/shunsoku/issues/32)、M2 [#33](https://github.com/wchoco/shunsoku/issues/33)、M3 [#34](https://github.com/wchoco/shunsoku/issues/34)、M4 [#35](https://github.com/wchoco/shunsoku/issues/35)（M4-16 は [#122](https://github.com/wchoco/shunsoku/issues/122)、M4-17〜M4-40 は書き込みの拡張の spec [#143](https://github.com/wchoco/shunsoku/issues/143) のチケット #144〜#151、#159、#157、#155。M4-23 は #154 で、M4-24 は #155 で直した）、M5 [#36](https://github.com/wchoco/shunsoku/issues/36)。

マイルストーンを足したら、その spec の表をここに写す。
