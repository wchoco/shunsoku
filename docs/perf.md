配布物そのもの（`cargo build --release` の `shunsoku.exe`）の性能を、マイルストーンごとに同じ方法で測って残す。

目標値は参考として置くだけで、リリース条件にはしない（spec #32）。

| 指標 | 目標（参考） |
|---|---|
| 常駐時のメモリ | 30MB |
| ホットキーから範囲選択の画面まで | 100ms |
| コールドスタート | 500ms |
| 書き込みの更新 | 16ms |

## 指標の定義

- **常駐時のメモリ**: 本体の Private Working Set（タスク マネージャーの「メモリ」、性能カウンターの `Working Set - Private`）。トレイに登録して 5 秒たった時点の値を正式値にする。次の 2 つは参考値として、参考値の累積表に書く。
  - 撮影 10 回後: 範囲選択の画面を開き、主モニタの (100, 100) から (300, 250) までドラッグしてスクラップを出し、そのスクラップを Esc で閉じるのを 10 回くり返して、2 秒たった時点（取得・読み戻し・スクラップの経路を通す）。本体が区切り `scrap_shown` を書かない版では、範囲選択の画面を開いて Esc で閉じるだけになる。
  - スクラップ 1 枚表示中: 主モニタの (100, 100) から (500, 400) までドラッグしてスクラップを 1 枚出し、2 秒たった時点。本体が区切り `scrap_shown` を書かない版では測れない（「測れなかった」と出る）。
- **ホットキーから範囲選択の画面まで**: ハーネスが `SendInput` でホットキーを送る直前から、本体で全モニタの `DwmFlush` が返るまで。1 回起動したまま、画面を開いて Esc で閉じるのを 20 回くり返す。
- **コールドスタート**: ハーネスがプロセスを作る直前から、本体でトレイの登録が終わるまで。1 回ごとに起動し直す。OS のファイル キャッシュは消さないので、厳密な「初回」ではない。
- **書き込みの更新**: 書き込みの編集モードの入力でスクラップを描き直し始めてから（区切り `annotate_paint_start`）、ウィンドウに出し終えるまで（`annotate_paint_end`）の 1 回分。主モニタと同じ大きさの白紙スクラップ（白・不透明）を 1 枚出し、編集モードでフリーハンドを選んで、主モニタの中央を回る 200 歩のドラッグを `SendInput` で送る。1 歩ごとに描き直しが出るのを待ってから次の歩を送り（1 秒で出なければその歩は飛ばす）、ドラッグの間の描き直しの 1 回ずつを値にする。1 回起動したまま 1 回のドラッグで測り、`--runs` は使わない。

中央値は、回数が偶数なら真ん中の 2 つの平均。p90 は最近順位法（小さい方から ceil(0.9 × 回数) 番目、20 回なら 18 番目）で、補間はしない。計算は `shunsoku_core::perf::Summary` にある。

## 測り方

1. 常駐している shunsoku を終了する（ハーネスは常駐を見つけると止まる）。
2. リリース ビルドを作る。

   ```sh
   cargo build --release -p shunsoku -p perf-harness
   ```

3. 測る。指標を書かなければ、常駐時のメモリ・ホットキーから範囲選択の画面まで・コールドスタートの 3 つを測る。書き込みの更新は `annotate` を書いたときだけ測る。数分かかり、その間はキーボードとマウスに触らない（書き込みの更新は実機の入力を乗っ取る）。

   ```sh
   target\release\perf-harness.exe target\release\shunsoku.exe
   # 指標を絞る・回数を変える・ホットキーを変える
   target\release\perf-harness.exe target\release\shunsoku.exe cold-start hotkey --runs 20 --hotkey "Ctrl+Alt+Shift+F9"
   # 書き込みの更新
   target\release\perf-harness.exe target\release\shunsoku.exe annotate
   ```

4. 最後に出る `docs/perf.md の行` を累積表に貼り、マイルストーンと日付を埋める。参考値は、出力の「参考」の中央値と p90 を参考値の累積表に書く。書き込みの更新は、`docs/perf.md の書き込みの更新の行` を書き込みの更新の表に貼る。p90 が中央値よりずっと大きいなど、計測中の操作でぶれたと思われるときは測り直す。

### しくみ

- 本体は、環境変数 `SHUNSOKU_PERF_LOG=<パス>` があるときだけ、区切りごとの QPC の時刻をそのファイルに書く。ないときは何も書かない。cargo feature では切り替えないので、配布物と同じ exe を測れる。
- ログは 1 行目が `frequency <QPC の周波数>`、そのあと 1 区切り 1 行の `<区切り> <QPC のカウント>`。区切りは次のとおり。

  | 区切り | 時点 |
  |---|---|
  | `process_start` | プロセスの開始（`main` に入った直後） |
  | `tray_registered` | トレイの最初の登録の完了（起動時に登録できなければ、`TaskbarCreated` のあとに初めて登録できた時点） |
  | `hotkey_received` | ホットキーの受信（`WM_HOTKEY`） |
  | `overlay_flushed` | 範囲選択の画面を出し、全モニタで `DwmFlush` が返った時点 |
  | `scrap_shown` | スクラップを 1 枚出し終えた時点 |
  | `annotate_paint_start` | 書き込みの編集モード中のスクラップの描き直しを始めた時点（編集モードの入力で描き直すたび） |
  | `annotate_paint_end` | その描き直しをウィンドウに出し終えた時点。描けなかったときは書かない |

- ハーネス（`tools/perf-harness`、開発専用で zip には入れない）は、一時フォルダを `APPDATA` にして本体を起動する。そこにハーネスのホットキーだけを書いた `settings.toml` を置くので、ユーザーの設定とログには触れない。本体は起動時に自動起動の登録を同期するので、`SHUNSOKU_AUTOSTART_VALUE` を `shunsoku-perf-harness` にして、ユーザーの Run キーの値（`shunsoku`）にも触れさせない。途中で失敗したときは、その一時フォルダ（本体の `shunsoku.log` と区切りのログ）を残す。
- 書き込みの更新では、作業フォルダの `settings.toml` に、主モニタ全体を白紙スクラップにする定型領域（ホットキー `Ctrl+Alt+Shift+F10`、背景は白）を足して起動し、そのホットキー・`E`（書き込みの編集モード）・`6`（フリーハンド）を送ってからドラッグする。始まりと終わりの組は `shunsoku_core::perf::PerfLog::spans` で作る（終わりの書かれなかった始まりは捨てる）。測り終えたら設定をハーネスのホットキーだけに戻す。
- QPC はプロセスをまたいで同じ時計なので、ハーネスの時刻（`SendInput` の直前、プロセスを作る直前）と本体の区切りの時刻をそのまま引き算する。
- Private Working Set は `QueryWorkingSet` で本体のワーキング セットのページを列挙し、共有できないページを数えて求める。`GetProcessMemoryInfo` の `PrivateUsage` はコミット（Private Bytes）で、別の値なので使わない。
- 測った時点のメモリには、ハーネスの操作で開いた画面の名残（GPU のメモリの戻り具合など）も入る。比べるのは同じハーネスで測った値どうしにする。
